# 多引擎网页与图片搜索（astrbot_all_search）

一个独立的 AstrBot 插件：让 AI 在 **必应（cn.bing.com）**、**百度（www.baidu.com）**、
**哔哩哔哩（api.bilibili.com）** 上搜索公开网页与视频，按需筛选时效并引用来源，
也可以单独搜索并转发图片（必应 / 百度）。

> **网页搜索与图片转发是两项完全独立的能力。**普通网页搜索不会附带图片，也不会触发图片转发。

## 命令一览（统一命令）

| 命令 | 说明 |
| --- | --- |
| `/搜索 [搜索引擎] <关键词>` | 网页 / 视频搜索 |
| `/search [搜索引擎] <关键词>` | 同上（英文兼容） |
| `/搜图 [搜索引擎] <关键词>` | 图片搜索并转发 |
| `/image [搜索引擎] <关键词>` | 同上（英文兼容） |

**旧的 `/bing搜索`、`/bing搜图`、`/bing_search`、`/bing_image` 已移除**，不再响应，请使用上表命令。

### 搜索引擎参数

搜索引擎写在关键词**前面**，可省略：

| 引擎 | 可用写法 |
| --- | --- |
| 必应 | `bing`、`必应` |
| 百度 | `baidu`、`bd`、`百度` |
| 哔哩哔哩 | `bilibili`、`bili`、`b站`、`哔哩哔哩`、`哔哩`、`哔站` |

- **省略引擎** → 并发搜索全部已启用引擎并合并结果（可通过 `merge_all_engines` 关闭）。
- 也支持逗号列举多个引擎：`/搜索 bing,百度 关键词`。
- 引擎名可大小写混写（`BING`、`Baidu` 均可）。

### 使用示例

```
/搜索 人工智能发展趋势            # 三个引擎都搜，合并结果
/搜索 bing 人工智能发展趋势        # 只搜必应
/搜索 百度 天气预报               # 只搜百度
/搜索 bili 罗翔                  # 只搜哔哩哔哩，返回视频直链 + 视频简介
/search bd 关键词                # 英文命令 + 百度
/搜图 橘猫                       # 必应 + 百度图片，合并转发
/搜图 bing 橘猫                  # 只搜必应图片
/image baidu 橘猫                # 只搜百度图片
```

> 注意：由于引擎名写在关键词前，`/搜索 bing 是什么` 会被理解为「用必应搜索『是什么』」。
> 若想搜索短语本身，请不加引擎（默认多引擎），或改写关键词。

### 各引擎能力对照

| 引擎 | 网页 / 视频搜索 | 图片搜索 |
| --- | --- | --- |
| 必应 | ✅ | ✅ |
| 百度 | ✅（受出口 IP 影响，见下） | ✅ |
| 哔哩哔哩 | ✅ 返回视频直链 + 视频简介 | ❌ 不支持，会明确提示 |

## 能力一览（自然语言 / AI 工具）

| 能力 | 工具名（保留旧名 + 新增通用名） |
| --- | --- |
| 网页 / 视频搜索 | `web_search_bing`、`web_search` |
| 图片搜索转发 | `image_search_bing`、`image_search` |

两个工具都新增了 `engine` 参数（可选），留空表示按默认引擎策略执行。
**图片转发**在**工具调用期间**由插件直接发送到当前对话；调用方只收到**不含图片直链**的
文字回执（含成功 / 失败数量）。命令路径则通过消息链直接返回图片。

## 配置项（WebUI 可视化）

### 总开关

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 插件总开关；关闭后不发起搜索请求。 |
| `enable_web_search` | `true` | 单独控制网页工具与网页命令。 |
| `enable_image_search` | `true` | 单独控制搜图工具与搜图命令。 |

### 引擎开关与地址

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `enable_bing` | `true` | 是否允许必应参与搜索。 |
| `enable_baidu` | `true` | 是否允许百度参与搜索。 |
| `enable_bilibili` | `true` | 是否允许哔哩哔哩参与搜索。 |
| `bing_host` | `cn.bing.com` | 必应地址来源。 |
| `baidu_host` | `www.baidu.com` | 百度地址来源。 |
| `bilibili_host` | `api.bilibili.com` | 哔哩哔哩搜索 API 主机名。 |

### Cookies（默认留空）

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `baidu_cookies` | 空 | **可选。**被百度拦截时填写浏览器里的 `baidu.com` Cookie 可显著提高成功率。 |
| `bilibili_cookies` | 空 | **可选。**哔哩哔哩搜索接口不带 Cookie 也能用；填写（如含 `buvid3`）可提升稳定性。 |

### 条数与合并策略

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `merge_all_engines` | `true` | 不指定引擎时是否搜索全部已启用引擎。 |
| `default_engine` | `bing` | 关闭全引擎合并时使用的默认引擎。 |
| `merge_total_count` | `5` | 多引擎合并后结果总条数上限，范围 1-50。 |
| `default_count` | `5` | 单引擎网页结果数，范围 1-50。 |
| `default_bilibili_count` | `5` | 哔哩哔哩视频条数，范围 1-20。 |
| `default_image_count` | `3` | 默认转发图片数，范围 1-5。 |

### 输出与网络

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `need_summary` | `true` | 是否展示摘要；哔哩哔哩对应视频简介。 |
| `need_url` | `true` | 是否附带来源地址；哔哩哔哩对应视频直链。 |
| `need_content` | `false` | 是否抓取完整正文，建议保持关闭。**本版本仅保留配置项。** |
| `timeout_seconds` | `30` | 单次请求超时，范围 5-120 秒。 |
| `max_snippet_chars` | `1200` | 每条结果最大字符数，范围 200-8000。 |

## 百度可用性说明（重要）

百度对服务器 IP 的反爬非常强：同一台机器在**相同时段内**可能一次返回真实结果、
下一次就被 302 重定向到 `wappass.baidu.com` 的安全验证页。

**能否搜索成功主要取决于服务器出口 IP，不是插件代码可以完全解决的。**插件为此提供了：

1. 请求前先访问百度首页预热 Cookie（`BAIDUID` 等），再带完整浏览器请求头发起搜索。
2. `baidu_cookies` 配置项：从浏览器复制已登录/已通过验证的 `baidu.com` Cookie 填入，
   可显著提高成功率。
3. 命中验证页或解析不到结果时，回执会明确提示「触发安全验证，请填写百度 Cookies」。
4. 实在不可用时，可通过 `enable_baidu` 单独关闭百度，不影响必应与哔哩哔哩。
5. **必应与哔哩哔哩不受此影响**，可稳定使用。

## 生命周期

```
网页请求 -> 并发搜索各引擎 -> 归一化结果 -> 按引擎顺序合并去重 -> 带来源的受限摘要 -> AI 组织回答
图片请求 -> 并发搜索各图片引擎 -> 插件直接发图到当前对话 -> AI 收到不含图片直链的回执
```

## 安装与兼容性

- **AstrBot**：`>=4.26.7`（`metadata.yaml` 中声明，仅设最低版本，不设 4.x 小版本上限）
- **平台**：`aiocqhttp`
- **Python 依赖**：仅使用 AstrBot 已内置的 `aiohttp`，无需额外安装。

将本插件目录放入 AstrBot 的 `data/plugins/` 下，重启或在 WebUI 中重载插件即可。

## 设计说明

- **多引擎并发**：各引擎独立会话与独立超时，并发执行后按固定顺序合并，输出稳定。
- **去重按 URL**：仅对相同 URL 去重，同一主题的不同来源会保留。
- **部分成功也返回**：某个引擎失败时，其余引擎的结果照常返回，并在末尾注明失败原因。
- **来源可核对**：网页结果包含标题、摘要和公开来源地址；哔哩哔哩结果包含视频直链与简介。
- **上下文可控**：每条结果长度可通过 `max_snippet_chars` 限制，合并条数由 `merge_total_count` 限制。
- **图片直接发送**：图片在工具调用期间发到当前对话，不把图片直链交给 AI 重发。
- **失败不泄密**：日志与回执只记录稳定错误码（如 `E_TIMEOUT`、`E_BAIDU_BLOCKED`），
  不回显 Cookies、API Key 或远端错误正文。
- **健壮性**：某张图片发送失败时会继续尝试剩余图片，并在回执中准确报告成功与失败数量。
